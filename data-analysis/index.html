1已知 X = [1,2,3,4,5], Y = [2,4,5,4,5]。用最小二乘法求简单线性回归方程 ŷ = a + bx，并计算 R²。
x̄ = 3, ȳ = 4
Σ(x-x̄)(y-ȳ) = (-2)(-2)+(-1)(0)+0(1)+1(0)+2(1) = 6
Σ(x-x̄)² = 4+1+0+1+4 = 10
b = 6/10 = 0.6
a = ȳ - bx̄ = 4 - 0.6×3 = 2.2
方程：ŷ = 2.2 + 0.6x

SST = Σ(y-ȳ)² = 4+0+1+0+1 = 6
SSR = b²Σ(x-x̄)² = 0.36×10 = 3.6
R² = SSR/SST = 3.6/6 = 0.6（60%）
2某 Logistic 回归模型输出：logit(p) = -2.0 + 0.5x₁ + 1.2x₂。当 x₁=4, x₂=1 时，预测事件发生概率，并解释各系数的含义。
logit(p) = -2.0 + 0.5×4 + 1.2×1 = -2 + 2 + 1.2 = 1.2
p = e^1.2 / (1 + e^1.2) ≈ 3.320 / 4.320 ≈ 0.769 ≈ 76.9%

系数解释：
β₀ = -2.0：当 x₁=x₂=0 时，log-odds = -2.0
β₁ = 0.5：x₁ 每增加1单位，odds 变为原来的 e^0.5 ≈ 1.65 倍
β₂ = 1.2：x₂ 每增加1单位，odds 变为原来的 e^1.2 ≈ 3.32 倍
x₂ 对结果的影响大于 x₁
3某回归模型有三个自变量，相关系数矩阵显示 r₁₂=0.85, r₁₃=0.78, r₂₃=0.92。计算 VIF 并判断是否存在多重共线性问题。
对于变量1：R₁² ≈ 1 (因为 r₁₂² 和 r₁₃² 都很高)
使用简化公式：VIFⱼ = 1 / (1 - Rⱼ²)

以变量2为例，近似计算 VIF ≈ 1/(1-0.92²) ≈ 1/(1-0.8464) ≈ 6.5
结论：VIF > 5，存在严重多重共线性，建议剔除变量2或3之一，或进行PCA降维。
4某 Beta-Binomial 共轭模型：先验 Beta(2,5)，观测到 10 次试验中成功 7 次。求后验分布，并计算后验均值。
先验：Beta(α=2, β=5)
似然：Binomial(n=10, k=7)

共轭性质：后验 = Beta(α+k, β+n-k)
= Beta(2+7, 5+10-7) = Beta(9, 8)

后验均值 = α' / (α'+β') = 9 / (9+8) = 9/17 ≈ 0.529
先验均值 = 2/7 ≈ 0.286，数据均值 = 7/10 = 0.7
后验均值介于先验与数据之间，体现了贝叶斯更新的平衡。

1某员工数据集包含以下字段：姓名、年龄、入职日期、工资。发现部分数据存在以下问题：① 3条年龄记录缺失；② 2条工资为-5000（不合理）；③ 入职日期格式不统一（有"2023/01/15"、"15-01-2023"、"2023年1月15日"）。请设计清洗方案。
清洗方案：
① 年龄缺失：用同部门员工年龄中位数填充，或建立基于职位的回归模型预测
② 工资异常：-5000 可能是录入错误，检查原始记录；若确认错误，用同职位平均工资填充，或删除该记录
③ 日期格式：统一转换为 ISO 标准格式 "YYYY-MM-DD"，使用 datetime 解析
额外建议：建立数据校验规则（年龄 18-65，工资 >= 0），从源头减少脏数据
2某销售数据集中"客户地区"字段有以下值：北京、北京市、BJ、上海、沪、shanghai、广州、Guangzhou。如何规范化该字段？
规范化步骤：
1. 建立标准映射表：北京 → 北京，北京市 → 北京，BJ → 北京
2. 统一大小写：全部转为小写后匹配
3. 模糊匹配：使用字符串相似度（如 Levenshtein 距离）处理拼写错误
4. 最终输出标准化为：北京、上海、广州
工具推荐：OpenRefine、Python fuzzywuzzy 库
3某数据集有 1000 条记录，其中 80 条缺失"年龄"，50 条缺失"收入"，30 条同时缺失两者。用箱线图法检测"收入"异常值，已知 Q1=5000, Q3=15000。请计算异常值边界。
IQR = Q3 - Q1 = 15000 - 5000 = 10000
下界 = Q1 - 1.5×IQR = 5000 - 15000 = -10000
上界 = Q3 + 1.5×IQR = 15000 + 15000 = 30000
异常值判断：收入 < -10000 或 > 30000 为异常值
由于收入通常为非负数，实际下界为 0
最终异常值边界：收入 > 30000 视为异常高值
缺失值处理：80+50-30=100 条至少缺失一个字段，可考虑删除（仅10%），或分别填充
4某用户行为日志中，发现同一用户在同一秒内产生了 200 条记录（正常用户约为 1-5 条/秒）。请判断这是什么类型的数据问题，以及如何处理。
问题类型：异常值（离群点）或爬虫/机器人行为

处理方案：
1. 业务判断：确认是否为正常业务场景（如批量操作）
2. 若是爬虫：标记并删除或单独分析
3. 若是数据重复：按用户+时间窗口去重，保留第一条
4. 建立监控规则：同一用户每秒超过 20 条记录触发告警
5. 使用滑动窗口统计：计算每分钟请求数，识别异常模式
5某问卷数据集包含多选题字段，原始格式为字符串（如"A,B,C"）。需要转换为适合分析的形式。请设计转换方案，并说明如何计算选择率。
转换方案：
1. 拆分字符串：按逗号分隔，得到每个选项的列表
2. 独热编码（One-Hot Encoding）：为每个选项创建一列（A、B、C、D...），选中为1，未选为0
3. 数据框形式：每行一个受访者，每列一个选项

选择率计算：
某选项选择率 = 选择该选项的人数 / 总受访人数 × 100%
例如：100 人中 60 人选择了 A，则 A 的选择率 = 60%

2某商品销量数据呈现明显季节性波动。描述如何分解时间序列，并解释各组成部分的含义。若1-3月数据为 [120, 90, 150]，用3期移动平均计算趋势值。
时间序列分解：Y = T + S + C + I（趋势 + 季节 + 周期 + 随机）

各组成部分：
- 趋势（T）：长期发展方向
- 季节性（S）：固定周期内的重复波动
- 周期性（C）：非固定周期的波动
- 随机性（I）：不可解释的噪声

3期移动平均（第2期）：
MA₂ = (120 + 90 + 150) / 3 = 360 / 3 = 120

趋势值：第2期趋势值 ≈ 120（平滑后消除了部分季节波动）
3某数据集中两个变量 X 和 Y 的皮尔逊相关系数为 0.85。这是否意味着 X 导致 Y？请解释原因，并给出可能的替代解释。
不意味着 X 导致 Y。相关 ≠ 因果。

可能原因：
1. 反向因果：Y 可能是 X 的原因，而非结果
2. 混淆变量：存在第三个变量 Z 同时影响 X 和 Y
例：冰淇淋销量与溺水事故高度相关，但原因是"气温"
3. 巧合相关：纯属偶然，尤其是在小样本中
4. 选择偏差：数据来源本身存在系统性偏差

正确做法：建立对照实验（A/B测试）或采用工具变量、因果推断方法（如DID）来验证因果关系。
4某数据集包含客户满意度评分（1-10分）和复购率。分析发现满意度与复购率的相关系数仅为 0.15。这是否说明满意度不重要？如何进行更深入的分析？

6. 因果分析：进行 A/B 测试验证满意度提升是否带来复购增长
5某特征（如用户浏览时长）呈现严重右偏分布（长尾）。请说明这对建模的影响，以及常用的处理方法。
右偏分布的影响：
1. 均值被极端大值拉高，不能代表典型值
2. 违反线性回归的正态性假设
3. 距离计算受极端值影响（如KNN、K-Means）
4. 模型对少数极端样本过度敏感

处理方法：
1. 对数变换：log(1+x) 能有效压缩长尾
2. 平方根变换：适用于计数数据
3. Box-Cox 变换：自动寻找最优变换参数
4. 分箱处理：将连续值转为离散分位数组

2某推荐系统 A/B 测试：对照组转化率 5%，实验组 5.5%，每组样本 10000 人。判断实验是否显著，并计算提升率与置信区间。
H₀: p₁ = p₂, H₁: p₁ ≠ p₂, α = 0.05

对照组：n₁=10000, x₁=500, p̂₁=0.05
实验组：n₂=10000, x₂=550, p̂₂=0.055

合并比例 p̂ = (500+550)/(10000+10000) = 0.0525
SE = √[p̂(1-p̂)(1/n₁+1/n₂)] = √[0.0525×0.9475×0.0002] ≈ 0.00315
z = (0.055-0.05) / 0.00315 ≈ 1.587
z₀.₀₂₅ = 1.96, |z| = 1.587 < 1.96
结论：差异不显著（p ≈ 0.113）

提升率 = (5.5-5)/5 = 10%
95% CI 差值：0.005 ± 1.96×0.00315 ≈ [-0.0012, 0.0112]
3某分类模型在1000条测试数据上表现：真正例(TP)=80，假正例(FP)=20，真反例(TN)=850，假反例(FN)=50。请计算精确率、召回率、F1-score，并分析模型偏向。

| | 预测正 | 预测负 |
| 实际正 | TP=80 | FN=50 | 实际正=130
| 实际负 | FP=20 | TN=850 | 实际负=870

精确率 P = TP/(TP+FP) = 80/100 = 80%

1某销售表 sales(sales_id, employee_id, sales_amount, sales_date)。请查询每个员工每月销售额，以及该员工截至当月的累计销售额（YTD）。
SELECT
  employee_id,
  DATE_FORMAT(sales_date, '%Y-%m') AS month,
  SUM(sales_amount) AS monthly_sales,
  SUM(SUM(sales_amount)) OVER (
    PARTITION BY employee_id
    ORDER BY DATE_FORMAT(sales_date, '%Y-%m')
    ROWS UNBOUNDED PRECEDING
  ) AS ytd_sales
FROM sales
GROUP BY employee_id, DATE_FORMAT(sales_date, '%Y-%m')
ORDER BY employee_id, month;

关键点：SUM() OVER() 窗口函数实现累计求和，PARTITION BY按员工分组，ORDER BY按月份排序。
2某用户登录表 user_log(user_id, login_time)。请查询每个用户的连续登录天数（假设用户可能一天登录多次）。
解题思路（去重后用日期差分组）：

WITH daily_log AS (
  SELECT DISTINCT user_id, DATE(login_time) AS login_date
  FROM user_log
),
grouped AS (
  SELECT *,
    DATE(login_date) -
    ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) AS grp
  FROM daily_log
)
SELECT user_id, COUNT(*) AS consecutive_days
FROM grouped
GROUP BY user_id, grp
ORDER BY consecutive_days DESC;

核心：日期减去行号，连续日期会得到相同值（grp），按grp分组即可统计连续天数。
3某表有员工工资(salary)。要求查询每个部门工资排名前3的员工，不允许使用LIMIT/ROWNUM（要求使用窗口函数）。
WITH ranked AS (
  SELECT *,
    DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rnk
  FROM employees
)
SELECT * FROM ranked WHERE rnk <= 3;

说明：
- DENSE_RANK() 处理并列情况（相同工资同排名）
- 若用 ROW_NUMBER()，并列只会选一个
- 若用 RANK()，并列会跳号（如两个第1名后下一个是第3名）
- DENSE_RANK() 最符合"前3"的业务需求（并列不额外占用名额）

DAX 度量值：

首次购买日期 = MIN('订单表'[订单日期])

最近购买日期 = MAX('订单表'[订单日期])

总购买次数 = COUNTROWS('订单表')

平均订单金额 = AVERAGE('订单表'[订单金额])

若要在客户维度表中显示（每行一个客户）：
在客户表中创建计算列：
首次购买 = CALCULATE(MIN('订单表'[订单日期]), RELATEDTABLE('订单表'))

或使用 RELATEDTABLE 直接在客户表中引用关联的订单记录。
2用DAX实现同期群分析（Cohort Analysis）：按用户首次购买月份分组，计算各组在后续月份的留存率。
同期群分析 DAX 实现：

1. 创建首次购买月份计算列（用户表）：
首次购买月份 = FORMAT(CALCULATE(MIN('订单表'[订单日期]), RELATEDTABLE('订单表')), "YYYY-MM")

2. 创建留存度量值：
留存用户数 =
VAR firstMonth = SELECTEDVALUE('用户表'[首次购买月份])
VAR currentMonth = SELECTEDVALUE('日期表'[月份])
RETURN
CALCULATE(
  DISTINCTCOUNT('订单表'[用户ID]),
  '用户表'[首次购买月份] = firstMonth,
  '日期表'[月份] = currentMonth
)

3. 在矩阵中：行 = 首次购买月份，列 = 订单月份，值 = 留存用户数

4. 计算留存率：留存率 = DIVIDE([留存用户数], [首月用户数], 0)

注意：需要建立日期表和用户表的适当关系。
3在Tableau中，某数据有（订单ID、客户ID、订单金额）。要求计算每个订单金额占该客户总订单金额的百分比。请用LOD实现。
Tableau LOD 实现：

1. 创建LOD计算字段"客户总金额"：
{FIXED [客户ID] : SUM([订单金额])}

解释：FIXED [客户ID] 表示对每个客户ID固定计算其总订单金额，
不受视图中的其他筛选器影响。

2. 创建百分比计算字段：
[订单金额] / [客户总金额]

3. 在视图中显示：
- 行：客户ID、订单ID
- 列：SUM([订单金额])、SUM([客户总金额])、AVG([百分比])
